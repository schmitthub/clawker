# Monitoring

- `internal/monitor/` owns Compose/collector/Prometheus generation and OpenSearch bootstrap assets.
- Prometheus stores metrics. OpenSearch stores logs/traces. OpenSearch Dashboards supplies their UI. The old Grafana/Loki notes are historical.
- Agent-specific telemetry comes from monitoring extensions. Keep agent-specific configuration out of generic infrastructure templates.
- `monitor.extensions` selects extensions through the bundle resolver. Selection enables an extension; there is no separate per-extension active flag.
- `monitor up` merges selected extensions into the host ledger and renders routes from the full seeded set.
- Keep other projects' seeded routes when one project changes its selection. Validate shared names and cluster-object claims before saving.
- `monitor reload` applies selection changes to a running stack. Removing volumes with `monitor down --volumes` removes the ledger.
- The collector endpoint is a base URL from config. Do not concatenate per-signal endpoints in bundler code.
- Trusted CP/Envoy/CoreDNS telemetry and agent telemetry have separate paths. Certificate provisioning packages under `controlplane/` have separate roles.
- The collector has a third receiver, `otlp/agents` on `monitoring.otel_agent_ingest_port` (default 4320, same server cert and infra client CA as `otlp/infra`). Only the CP gateway (`controlplane/otelgateway`) sends there; records carry CP-resolved `project`/`agent`/`container_id` and `ingest_source=cp_gateway` (`resource/agent_gateway` upserts it). Pipelines `traces/agents`, `metrics/agents`, `logs/agents` (logs → `routing/agents`, a connector with the unit lanes only and no `clawker-cli` route; unit pipelines and `logs/untrusted_unrouted` receive from both connectors). The untrusted `otlp` receiver (4317/4318, host loopback) stays for the host CLI; it is its only sender.
- The stack runs on the compose project's own network and never joins `clawker-net`. Every host publish binds `127.0.0.1`: OTLP 4317/4318 (host CLI), Prometheus, OpenSearch, Dashboards. The infra (`otel_infra_port`, 4319) and agent-ingest (`otel_agent_ingest_port`, 4320) receivers have no host publish; those settings set only the collector's container listener ports. CoreDNS forwards no monitoring hostname and `MonitoringServiceHostnames` is gone; agents reach the collector only through the CP gateway.
- Trusted telemetry uses the internal Docker network `clawker-telemetry` (`consts.TelemetryNetwork`, managed labels, `internal: true`). Members: `otel-collector`, the CP container, Envoy, CoreDNS. Agents never join it. One helper, `docker.Client.EnsureTelemetryNetwork`, creates it; CP bootstrap (`placeCPOnNetwork`), the firewall `Stack` network guard, and `monitor up`/`reload` (before compose up) call it. The compose file declares it `external: true`; only the collector service joins it (networks: default + telemetry). CP, Envoy, and CoreDNS join it as a second endpoint with a dynamic address; their `clawker-net` endpoint keeps its static IP. Trusted senders dial `otel-collector:<port>` through Docker embedded DNS: CP `OTEL_EXPORTER_OTLP_ENDPOINT=https://otel-collector:<OtelInfraPort>`, the gateway `otel-collector:<OtelAgentIngestPort>`, Envoy `otel_collector_als` (address, SNI, SAN pin = `otel-collector`), CoreDNS `CLAWKER_COREDNS_OTEL_ENDPOINT=otel-collector:<OtelInfraPort>`. Envoy and CoreDNS have no extra-hosts entry. The CP keeps `host.docker.internal:host-gateway` only for host-proxy resolution (per-container bypass). Collector server cert SANs: `otel-collector`, `localhost`, `127.0.0.1`; the SAN-drift heal re-mints a cert that lacks `otel-collector`. `IsMonitoringActive` checks only for a running `otel-collector` container. Design: `mem:plans/sandbox-hardening/monitoring-off-clawker-net/design`.
- Live ingest, routing, and certificate access need runtime proof. Template unit tests do not establish those results.
- Baked index patterns carry no `fields`. OpenSearch Dashboards 3.9 (data_views) reads an index pattern's field list from the saved object only and does not fetch it from the index at load time (3.6 did). Bootstrap writes each index pattern's field list from the live mapping after the saved-object import; without it every visualization that names a field fails with "Could not locate that index-pattern-field". Keep this step when the Dashboards image changes.
- A kept OpenSearch volume carries its ISM state: the 7-day retention deletes aged indices under a running stack. Monitoring UAT after a template change starts from `monitor down --volumes`.
- Package contract: `internal/monitor/AGENTS.md`. Runtime checks: `internal/monitor/AGENTS.md` → Runtime UAT. Detailed map and verification workflow: `.agents/skills/monitoring-checks/SKILL.md`.
