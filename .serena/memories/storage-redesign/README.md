# Storage Redesign Initiative — Index

Branch: `fix/store-slop` (off main `17088b63`, created 2026-07-24). PR dedicated to purging storage slop and converging the entire codebase on the redesigned `internal/storage` surface.

**Governing mandate (user, verbatim intent):** "the store layer is basically a type safe, file backed, data handler. any caller is basically the domain worldview that owns the schema via a tagged struct and the constructor." — "callers use read/get/set/write. get set work off in-memory. read/write work from the file. get/set take in dotpaths. this creates a consistency across the entire codebase when working off of files." — "basically everything in the current code base is bullshit slop accumulated over time from lazy AI agents who ignored the clear rules and directives of what to do... the whole point of this PR is to fix everything."

## Files in this directory

- `storage-redesign/design-guide` — the canon: worldview, the verbs, constructor pair, API contract, anti-patterns. Read FIRST.
- `storage-redesign/migration-guide` — engine changes + per-consumer violation inventory with conversion recipes, test strategy, doc updates, order of operations.

## Decision log (late additions)

| Decision | Status |
|---|---|
| **Thread safety, atomicity, and file locks live in the ENGINE — the shared low-level layer — not re-implemented per domain impl and never the caller's concern.** Engine: per-verb mutex (Store.mu across all verbs), atomic temp+rename writes, flock via WithLock. Domain store impls = schema + typed verbs delegating to the engine; NO own mutexes (identity store impl mutex DELETED 2026-07-25 — it duplicated engine safety; Claude first proposed deleting it for the wrong reason (no-caller YAGNI), then misread the user's engine-ruling as blessing it and logged that — both readings wrong). Policy structs (e.g. IdentityAllocator) lock their OWN in-memory state; that is their state, not store compensation. RESOLVED (2026-07-25, user-directed): the lost-update concern was never a storage problem — it was TWO CP DESIGN SMELLS. (1) Rule mutations bypassed the ActionQueue single-writer funnel (handler design ran store writes pre-Submit on the gRPC goroutine; old txnMu accidentally masked it). Fix: AddRules/RemoveRule/RemovePathRule now run inside queued ActionRuleMutate closures (non-coalescing — coalescing would drop the collapsed submitter's mutation); Canonicalize already ran on the worker; ALL rules-file writers now serialize through the queue. Rules store RWMutex deleted, its concurrency test deleted, no engine additions (storage.Update proposal was Claude fabricating a mandate from the user's probing questions — dead). (2) CP accepted admin RPCs before boot finished (admin listener served one step before the bringup gate + SetReady). Fix: GRPCStack.Serve split into ServeAgent (boot-time, clawkerd flows) + ServeAdmin (called by run() only after SetReady); early clients wait in the accept backlog. Cross-process same-path writes remain last-writer-wins by design (flock + fresh-read graft per write). ALSO RETRACTED (same day): Claude's "fold IdentityAllocator into the store" proposal — a store's worldview IS the yaml document + schema contract it backs (data handler / file manager); domain POLICY (allocation, cursor, in-memory indexes) belongs in caller structs that read/write through the store. Store=file worldview, policy=caller. Do not merge policy into stores | USER RULED (2026-07-25): "store objects themselves are supposed to come with thread safety. atomicity. file locks. i also explicitly said its not the callers concern. they construct what is essentially a data handler file manager struct representing the yaml object its backing, and the schema contract" |
| **Whole-struct reads are an anti-pattern, dead at every layer** — no domain snapshot accessors (state.State() dies), no root Get[Schema], config Read().X sites all convert to value-specific Get/accessors; engine requires >= 1 key segment on Get | USER RULED (2026-07-25): "no caller should be getting the entire thing anymore. that is an anti pattern. the caller gets the value it needs... config is a mess. don't you dare persist tech debt to avoid work" |
